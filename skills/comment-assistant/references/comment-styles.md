# Comment styles

| style | shape | use when |
| --- | --- | --- |
| Add a point | "<their point> + <one thing it connects to / a nuance>." | You know the topic; readers benefit. |
| Real question | "<detail they mentioned>: <question you want answered>?" | Genuinely curious; builds a thread. |
| Short experience | "This matched <specific situation> for me: <what happened>." | You have a relevant, true experience. |
| Specific praise | "<exact line or moment> was the best part, because <why>." | Nothing to add, but something landed. |
| Respectful pushback | "Agree on <x>. For <specific case>, I've seen <y> work better because <reason>." | You disagree with a reason. |
| Example | "One way this shows up: <concrete example>." | The post is abstract; make it concrete. |
| Resource in words | "<Name of book/tool/method> covers this well, especially <part>." | Only well-known, relevant, non-promotional resources. No links. |
| Build-on | "And the step after <their step> is <next step>." | Process posts. |
| Celebrate | "Congrats on <specific milestone>. <specific detail> must have taken ages." | Milestone posts by peers. |

## Rules

- Lead with the detail, not with "Great post".
- One idea per comment.
- Write like a person in the comments: short, lowercase is fine if the creator writes that way.
- Do not promote, link, or tag yourself. People click profiles that leave good comments; that is the whole mechanism.
- Never post the same comment twice.
